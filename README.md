# hillel-eks-practice

Навчальний кластер EKS для блоку «Хмари» курсу DevOps в IT Hillel.
Заняття 8 і далі.

Конфігурація свідомо спрощена для навчання. Кожне спрощення позначено
коментарем у коді з поясненням, як це роблять у продакшні.

---

## Що тут лежить

```
cluster/          Уся конфігурація Terraform: один воркспейс, один стан.
lessons/          Файли, які ви копіюєте в cluster/ по мірі просування курсу.
apps/shop/        Маніфести застосунку, які Flux розгортає в кластер.
infrastructure/   Компоненти кластера, які ставить Flux (з заняття 10).
docs/             Покрокові інструкції занять.
```

**Одна конфігурація, один воркспейс.** Нові можливості додаються копіюванням
файлів із `lessons/` у `cluster/`, а не окремими конфігураціями. Чому саме
копіюванням, а не одразу — див. `lessons/README.md`.

## Що змінилося після заняття 8

Минулого разу кластер у більшості не піднявся. Причин було дві, і обидві
виправлено.

**1. Типи машин недоступні на Free plan.** На акаунтах, створених після
15 липня 2025 на Free plan, дозволені лише `t3.micro`, `t3.small`, `t4g.micro`,
`t4g.small`, `c7i-flex.large`, `m7i-flex.large`. Ми вказували `t3.medium` —
його там немає. Тепер за замовчуванням `c7i-flex.large` (чому саме він —
нижче, у розрахунку ресурсів).

**2. Прихований баг із доступом.** Кластер створює роль HCP Terraform, і права
адміністратора отримує саме вона. Ваш власний користувач IAM без окремого запису
отримав би `Unauthorized` на будь-яку команду `kubectl`. Тепер є змінна
`cluster_admin_arns`, куди ви вписуєте свій ARN.

**3. Ліміт подів знято prefix delegation.** Див. розділ про ресурси нижче.

**4. Spot лишився за замовчуванням — але з запасним варіантом.** Ми не змогли
підтвердити в документації AWS, що spot-машини працюють на Free plan. Якщо
вузол не піднімається, поставте `node_capacity_type = "ON_DEMAND"`.

## Перед початком: перевірте квоту процесорів

Нові акаунти мають обмеження на кількість віртуальних процесорів. Один вузол —
це 2 vCPU. **Квоти для spot і on-demand окремі:**

| Модель | Квота в Service Quotas → Amazon EC2 |
|---|---|
| SPOT (за замовчуванням) | All Standard (A, C, D, H, I, M, R, T, Z) Spot Instance Requests |
| ON_DEMAND | Running On-Demand Standard (A, C, D, H, I, M, R, T, Z) instances |

Значення має бути щонайменше **2**. Якщо менше — *Request increase*; на невеликі
збільшення AWS зазвичай відповідає протягом години.

## Швидкий старт

### 1. Свій ARN

У **CloudShell** (іконка терміналу у верхній панелі консолі):

```bash
aws sts get-caller-identity --query Arn --output text
```

### 2. Воркспейс у HCP Terraform

Один, типу CLI-driven, з тегом `hillel-eks`. Змінні середовища (вкладка
**Environment variables**, не Terraform variables):

| Ключ | Значення |
|---|---|
| `TFC_AWS_PROVIDER_AUTH` | `true` |
| `TFC_AWS_RUN_ROLE_ARN` | ARN вашої наявної ролі |

> **Ім'я воркспейса має підпадати під шаблон `sub` вашої ролі.**
> Якщо роль дозволяє `workspace:workshop-*`, назвіть його `workshop-eks`.

### 3. Кластер

```bash
cd cluster
# впишіть організацію у блок cloud у versions.tf
cp terraform.tfvars.example terraform.tfvars   # впишіть prefix і свій ARN
terraform init
terraform apply                                # ~15 хвилин
```

### 4. Доступ

У CloudShell:

```bash
aws eks update-kubeconfig --region eu-central-1 --name <prefix>-eks
kubectl get nodes
```

### 5. Flux і застосунок

1. Зробіть **публічний форк** цього репозиторію на GitHub.
2. Скопіюйте файли заняття в загальну теку й додайте адресу форку:

```bash
cp lessons/09-flux/*.tf cluster/
cd cluster
# у terraform.tfvars:  git_url = "https://github.com/ваш-логін/hillel-eks-practice"
terraform init          # провайдер helm уже оголошений, init його підтягне
terraform apply
```

3. Перевірте в CloudShell:

```bash
kubectl get pods -n flux-system
kubectl get gitrepositories,kustomizations -n flux-system
kubectl get pods -n shop
kubectl port-forward -n shop svc/web 8080:80
```

4. Змініть `replicas` в `apps/shop/web.yaml` **у своєму форку**, закомітьте й
   за хвилину подивіться `kubectl get pods -n shop`. Ви нічого не застосовували —
   кластер сам підтягнув зміну.

### 6. Трафік і секрети (заняття 10)

```bash
cp -r lessons/10-traffic-secrets/. cluster/    # -r: разом із текою policies/
cd cluster
terraform apply
```

Далі — практики з `docs/lesson-10.md`: NLB через AWS Load Balancer Controller

## Розрахунок ресурсів

Мета — щоб після створення кластер вмістив усе, що знадобиться на наступних
заняттях, а не впав на другому ж поді.

### Проблема: ліміт подів на вузлі

З мережевим плагіном VPC CNI **кожен под отримує окрему адресу з VPC**, а
адреси прив'язуються до мережевих інтерфейсів машини:

```
max_pods = інтерфейси × (адрес_на_інтерфейс − 1) + 2
```

| Тип | vCPU | Пам'ять | Max pods за замовчуванням |
|---|---|---|---|
| `t3.micro` | 2 | 1 GiB | **4** — системні DaemonSet займають усе |
| `t3.small` | 2 | 2 GiB | **11** — на застосунки лишається 7 |
| `c7i-flex.large` | 2 | 4 GiB | **29** |
| `m7i-flex.large` | 2 | 8 GiB | **29** |

### Як це вирішують у продакшні: prefix delegation

Замість однієї адреси на слот інтерфейсу VPC CNI отримує **блок /28 —
шістнадцять адрес**. Ліміт подів перестає залежати від інтерфейсів.

Вмикається в доповненні vpc-cni — `ENABLE_PREFIX_DELEGATION = "true"`, див.
`cluster/eks.tf`. **Для керованої групи вузлів цього досить:** EKS сам перерахує
ліміт подів на вузлі. Окремо задавати `maxPods` у налаштуваннях kubelet потрібно
лише для self-managed вузлів, власних AMI або Karpenter.

Два обмеження: працює лише на машинах Nitro (усі сучасні типи, включно з нашими),
і має бути ввімкнено **до** появи вузлів. Вузли, створені раніше, покажуть
старий ліміт, доки їх не перестворити.

### Ціна: резерв пам'яті росте разом із maxPods

EKS резервує під систему **255 MiB + 11 MiB на кожен дозволений под**. Для
машин до 30 vCPU з prefix delegation ліміт зазвичай стає 110 — перевірте на
своєму вузлі командою нижче. Підняли ліміт — віддали пам'ять:

| maxPods | Резерв (+100 MiB на eviction) | allocatable на c7i-flex.large |
|---|---|---|
| 29 (за замовчуванням) | ~674 MiB | **~3.1 GiB** |
| 110 (з prefix delegation) | ~1565 MiB | **~2.2 GiB** |

### Що має влізти

| Що | Подів | CPU requests | Пам'ять requests | Точність |
|---|---|---|---|---|
| DaemonSet на вузлі | 4 | ~180m | ~120Mi | приблизно |
| CoreDNS | 2 | 200m | 140Mi | приблизно |
| Контролер дисків EBS | 2 | ~120m | ~360Mi | приблизно |
| Flux (4 контролери) | 4 | 400m | 256Mi | точно, з чарта |
| Застосунок shop | 4 | 200m | 128Mi | точно, з маніфестів |
| **Разом** | **16** | **~1100m** | **~1000Mi** | |

### Порівняння класів із нашою конфігурацією (prefix delegation, maxPods 110)

| Ресурс | Потрібно | `c7i-flex.large` | `t3.small` |
|---|---|---|---|
| Поди | 16 | 110 — **15%** | 110 — **15%** |
| CPU | ~1100m | ~1930m — **57%** | ~1930m — **57%** |
| Пам'ять | ~1000Mi | ~2235Mi — **45%** | ~335Mi — **не влазить** |

**Prefix delegation перенесла вузьке місце з подів на пам'ять.** На
`t3.small` поди тепер влазять, але резерв під 110 подів з'їдає майже всі 2 GiB.
Щоб усе-таки взяти `t3.small`, довелося б опустити maxPods приблизно до 30 —
тоді пам'яті лишається ~1.2 GiB, і наш бюджет влазить на 82%, без жодного
запасу на наступні заняття.

**Перевірте реальні числа самі:**

```bash
kubectl describe node <ім'я-вузла> | grep -A6 -E "Capacity|Allocatable"
kubectl describe node <ім'я-вузла> | grep -A8 "Allocated resources"
```

Усі числа тут приблизні: точна пам'ять, яку бачить ОС, залежить від типу машини
й версії образу.

## Режим життя кластера

```bash
NG=$(aws eks list-nodegroups --cluster-name <prefix>-eks --query 'nodegroups[0]' --output text)

aws eks update-nodegroup-config --cluster-name <prefix>-eks \
  --nodegroup-name $NG --scaling-config desiredSize=0     # наприкінці заняття
aws eks update-nodegroup-config --cluster-name <prefix>-eks \
  --nodegroup-name $NG --scaling-config desiredSize=1     # на початку наступного, ~3 хв

terraform destroy                                         # після останнього заняття блоку
```

**Чому не `terraform apply -var node_desired_size=…`.** Модуль EKS тримає
`desired_size` в `ignore_changes`, щоб Terraform не відкочував рішення
автомасштабувальника. Змінна `node_desired_size` задає лише кількість вузлів
при створенні групи, пізніші її зміни план просто не покаже. Ті самі команди
виводить `terraform output node_scale_commands`.

**Перед `destroy` приберіть усі сервіси типу `LoadBalancer`** (з заняття 10 —
закоментуйте `web-public.yaml`). Балансувальники й їхні security groups створює
контролер, а не Terraform, і `destroy` упреться у VPC.

**Нуль вузлів не означає порожній кластер.** Об'єкти Kubernetes зберігаються
у сховищі контрольного рівня, тому Deployment, Service і ConfigMap лишаються
на місці, а поди стають `Pending` і запускаються самі, щойно вузол повернеться.

**Нуль вузлів не означає нульовий рахунок.** Балансувальники від сервісів типу
`LoadBalancer` і томи EBS — ресурси AWS, вони тарифікуються незалежно від вузлів.
Саме тому публічний вхід `web-public` вмикається лише на час заняття, а решта
сервісів у `apps/shop` — типу `ClusterIP`.

### Скільки це коштує

| Позиція | На місяць цілодобово |
|---|---|
| Контрольний рівень | **$73** — завжди, навіть із нулем вузлів |
| Один вузол на spot | орієнтовно $15–30 |
| Той самий вузол on-demand | близько $70 |
| Диск і публічна адреса | ~$5 |
| **З вузлом у нулі між заняттями** | **~$75 за блок** |

Ціни вузлів орієнтовні: spot змінюється з часом і залежить від зони.

## Пастки, через які витрачають вечір

**`Unauthorized` у kubectl.** Ваш ARN не вписаний у `cluster_admin_arns`.
Кластер створювала роль платформи, а не ви.

**Вузол не піднімається.** Три можливі причини: тип машини недоступний на Free
plan, квота процесорів менша за 2 (квоти для spot і on-demand окремі!), або
spot недоступний на вашому акаунті — тоді `node_capacity_type = "ON_DEMAND"`.

**Вузол показує `pods: 29` після ввімкнення prefix delegation.** Вузол був
створений раніше. Перестворіть вузол: опустіть групу в 0 і поверніть 1
командами з розділу «Режим життя кластера».

**Flux не бачить репозиторію.** Форк приватний — зробіть його публічним. Або
гілка не `main`: чарт `flux2-sync` за замовчуванням дивиться в `master`.

**Перший plan з нуля падає на провайдері helm.** У `cluster/` уже лежать файли
Flux, а кластера ще немає. Спершу `terraform apply -target=module.eks`, потім
звичайний `terraform apply`.

**`exec: "aws": executable file not found`.** Приклад з інтернету з
`exec { command = "aws" }` у провайдері. На раннерах HCP Terraform немає AWS CLI —
токен треба брати через `data "aws_eks_cluster_auth"`, як у цьому репозиторії.

**Под `Pending` без видимої причини.** `kubectl describe pod` покаже причину
в подіях: найчастіше `Too many pods` або `Insufficient cpu`. Це і є ліміти
з розрахунку вище.

**Теги підмереж.** Без `kubernetes.io/role/elb` сервіс типу `LoadBalancer`
зависає у `Pending` назавжди.

**Версія Kubernetes.** Після 14 місяців стандартної підтримки кластер
автоматично коштує $0.60/год замість $0.10.

**Ім'я воркспейса й політика довіри.** Воркспейс з іменем поза шаблоном `sub`
дає `Not authorized to perform sts:AssumeRoleWithWebIdentity`.
